## Application Overview

This is the **Flight Reservation System (FRS)** — a classic IBM i demo/training application.

**Core program flow:**
- Entry: `FRS000` (logon) → menus in FLGHT400 (`FRSMAIN`, `FRSMANT`, `FRSREPT`)
- Main transaction: `FRS001` / `FRS001CL` (new order entry)
- Supporting programs: `FRS002`–`FRS009` (update/display/delete/FAX/select order)
- Maintenance: `FRS021`–`FRS024` (flights, cities, agents, customers)
- Selection subfiles: `FRS401`–`FRS413` (agents, cities, airlines, flights)
- Build utilities: `BFLGHT`, `BCUST` (populate test data)
- Utility subroutines: `RTRAND`, `RTDOFW`, `JTOGCV`, `GTOJCV` (random, date conversion)

**Modernization state (dual codebase):**

| Naming | Location | Style |
|---|---|---|
| `FRS0xx.RPG` | QRPGSRC | OPM RPG/400 (original) |
| `FRS0xx.RPGLE` | QRPGLESRC | ILE RPGLE **FREE (modernized) |
| `XXFRS0xx.RPGLE` | QRPGLESRC | Intermediate ILE conversion |
| `X2FRS0xx.RPGLE` | QRPGLESRC | Fully modernized with embedded SQL |
| Variants B/T/U/U2/X | QRPGSRC | 2004-era alternate versions |

## Critical Cross-Library Dependency: FLGHT400

**This is the most important non-obvious fact about this codebase.**

Every single FRS program (OPM and ILE alike) hardcodes the message file as a 20-character literal:

```
// OPM RPG I-spec:
I I  'FRSMSGF   FLGHT400  '    9  28 MSGF

// ILE RPGLE DCL-S:
DCL-S msgFile CHAR(20) INZ('FRSMSGF   FLGHT400  ');
```

This means:
- `FLGHT400` **must be on *LIBL** at runtime or all message sends will fail
- You cannot change the message file via library list alone
- The literal is replicated in ~25 source members

**Other FLGHT400 objects hardcoded at runtime:**

| Object | Type | Used by |
|---|---|---|
| `FRSMSGF` | *MSGF | All FRS programs |
| `CUSTOMERS` | *FILE | BLDCST.CLP, FRS001CL.CLP (via OVRDBF) |
| `FRS411DF` | *FILE | FRS411CL.CLP (DCLF — not overridable) |
| `MSGPANEL` | *FILE | MSGPRGH.CLP (DCLF — not overridable) |
| `FLDS` | *DTAARA | USECLEAR.CLP, USERESET.CLP |
| `FRSMAIN`, `FRSMANT`, `FRSREPT` | *MENU | FRS000 via GO command |

## Embedded SQL in OPM-named Members

`FRS022.RPG` (in QRPGSRC, `.RPG` extension) is actually `**FREE` ILE RPGLE with embedded SQL:
- Uses `EXEC SQL SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED`
- Uses `EXEC SQL COMMIT` for transaction control
- **Must be compiled with `CRTSQLRPGI`**, not `CRTRPGPGM` or `CRTBNDRPG`

Verify `FRS009.RPG` similarly before compiling.

## Compilation Notes

Documentation members (`FRS021DOC.`, `FRS401DOC.TXT`) show compile targets as `FLGHT400/xxx`.
When working in FLGHT403, adjust the library qualifier:

```
CRTBNDRPG PGM(FLGHT403/FRS0xx)
          SRCFILE(FLGHT403/QRPGLESRC)
          SRCMBR(FRS0xx)
          DFTACTGRP(*NO)
          ACTGRP(*NEW)          /* or *CALLER — see CTL-OPT in source */
          DBGVIEW(*SOURCE)
```

For embedded SQL members (FRS022, possibly FRS009):
```
CRTSQLRPGI OBJ(FLGHT403/FRS022)
           SRCFILE(FLGHT403/QRPGSRC)
           SRCMBR(FRS022)
           COMMIT(*NONE)
           DBGVIEW(*SOURCE)
```

## Code Style — Modernized RPGLE Patterns

- `**FREE` on line 1 (mandatory)
- Function key hex constants defined per-program (no shared copybook): `DCL-C F03 X'33';`
- Named indicator variables: `DCL-S exitFlag IND INZ(FALSE);` or full `INDDS`
- PSDS always `QUALIFIED` with named subfields (programName, status, jobName, etc.)
- Boolean inconsistency: some programs use `*ON`/`*OFF`, others use `'1'`/`'0'` — both exist
- API prototypes declared inline per program (no shared prototype source)
- Standard CTL-OPT options: `OPTION(*NODEBUGIO:*SRCSTMT)`
